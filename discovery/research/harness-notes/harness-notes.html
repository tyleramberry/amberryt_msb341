Agent Harness Engineering

A harness is everything between the model weights and the world: the loop, the context it assembles, the tools and skills it can reach for, the sub-agents it can spawn — and lately the code of the harness itself. Same weights, same benchmark, wildly different scores. These notes distill the history, then lay out the shortest path to building one.

The nine components — and where each one was invented

Every entry in the collection is the same move repeated: give the loop something new it is allowed to do. Here is the resulting anatomy, with the paper that first put each part in.

1. LoopCalls the model, runs what it asked for, decides whether to continue or stop.GPT-2 · Unsupervised Multitask Learners (2019) — a bare while-not-EOS loop, no tools, no memoryfor step in range(max_steps)

What actually varies between a 30% and a 95% run is not the weights but components 4–9 placed deliberately, plus one thing the papers never stop repeating: harness failures must not be mistaken for model failures. Prime Agent's own framing is that a low-friction membrane keeps the measurement pointed at the model's true capability.
02

The lineage, 2019 → 2026

2019 – 2022 · THE V0 HARNESS

A sampling loop and a prompt. Nothing else exists.

No tool calling, no skills, no memory. Two things you can do without leaving the context window: put examples in it, and let the model spend more tokens thinking inside it.

GPT-22019GPT-3 few-shot2020Chain-of-Thought2022
2021 – 2025 · STATIC HARNESSES — growing the action space

Give the loop something new it is allowed to do. The harness code stays fixed.

Search the web, call a tool, act and observe, critique itself, run code, spawn a peer, write a skill, edit its own memory, recurse. Ten papers, one move.

WebGPT2021ReAct2022Toolformer2023 Self-Refine2023Reflexion2023InterCode2023 Multi-Agent Collaboration2023Voyager2023MemGPT2023 Recursive Language Models2025
2023 – 2026 · LET THE HARNESS LEARN

The fixed part stops being fixed — prompt, then scaffolding, then the harness code, then online.

You cannot backpropagate through a prompt, so search over it instead. Then let the agent rewrite its own retrieval and memory code around a frozen model. Then mutate while it runs.

2026 · SHIPPED, AND MEASURED

Two systems built on everything above, plus the paper that makes progress visible at all.

Prime Agent
Persistent IPython REPL following the Recursive Language Model abstraction, recursive subagents, continual refinement of prompts and skills. 30% → 95.5% ARC-AGI-3
OpenJarvis
The same argument pointed at your laptop: five primitives, a frontier model searches the spec, everything runs locally. ~800× lower marginal cost
Long-task measurement
Capability as the length of task a system completes, not a single-turn score — the trend line that shows harness progress. Kwa et al. 2025

04

Which language

Pick by what you are building, not by taste. Python is the default answer for a first harness: the canonical 100-line reference is Python, every provider is one library away, the eval tooling is Python, and the most interesting shipped research harness (Prime Agent) is a Python-REPL machine.

LanguageChoose it whenProof in the collection
PythonYou are learning, benchmarking, training on trajectories, or want the shortest path to a working loop. mini-swe-agent (~100 lines, any model via litellm) · Prime Agent (MIT) · SWE-agent · Deep Agents · Claude Agent SDK · Antigravity SDK · OpenAI Agents SDK
TypeScriptThe harness ships inside a product or a UI, or you want to assemble one from real parts rather than write it. Pi SDK — pi-ai + pi-agent-core, MIT, "building your own harness from real parts", 16.7M npm/mo · eve (Vercel, Apache-2.0) · Claude Agent SDK
Rust / Zig / GoDistribution and start-up matter: a single small binary, embedded in a larger system. Exo (Rust, CLI, MIT — the harness edits its own code; $1.05 per task in FrontierHarness) · fx (Vercel Labs, 7.8 MiB Zig binary, embeddable)
Do not start with a framework. mini-swe-agent scored >74% on SWE-bench verified with no tool-calling API at all — bash is the only tool, history is strictly linear, and each action is an independent subprocess.run. That last detail is why sandboxing is a one-line swap to docker exec and why scale-out is trivial.
05

Where to start — a five-rung ladder

RUNG 1

Read one real harness end to end (~1 hour)

Three files: the agent class, the environment, the model wrapper. Nothing else is load-bearing. Then read Mini-SWE-agent's FAQ on why there is no persistent shell session — it is the design decision most people get wrong first.

DONE WHEN → you can name the loop, the tool interface and the exit condition from memory.
RUNG 2

Rebuild it yourself, from scratch, in Python (~half a day)

Start from minimal_harness.py next to this file. Keep it to four clearly separated functions: build_messages, call_model, run_command, run. Use the --selftest stub model so no API key is needed while you iterate on the loop.

DONE WHEN → --selftest passes and a real task completes against a live provider.
RUNG 3

Add the three things the minimal design deliberately omits (~1 day)

  • A sandbox: run actions in a container, not your home directory.
  • A transcript log: append-only, so a failed episode stops being wasted — this is Reflexion's seed.
  • A token/cost counter: budget tokens rather than calls; per-task cost is the metric nobody instruments early.
DONE WHEN → one run is reproducible from its transcript, and you know its cost.
RUNG 4

Build a 10-task eval before you add features (~1 day)

Ten small tasks with objective success criteria. Measure success rate and cost per task. Without this you cannot tell a harness improvement from noise — and the whole collection is an argument that capability should be measured as task horizon, not single-turn scores.

DONE WHEN → a one-line table: task, pass/fail, steps, tokens, dollars.
RUNG 5

Only now add components, one at a time, each re-measured

Order of value, cheapest first: skills (write verified routines to files), memory (managed context region), sub-agents (spawn as a tool call), then prompt optimization (DSPy/GEPA) and — if you get that far — letting the harness rewrite its own retrieval and memory code, as Meta-Harness does around a fixed model.

DONE WHEN → every component you added moved the eval, and you can show which run proved it.

Shortlist from the companion 51-tool list

Read first — the baseline

mini-swe-agent

~100 lines of Python, bash as the only tool, plain-text actions instead of tool calling, strictly linear history, independent subprocess.run per action. MIT, 7.5k stars. No skills, no memory, no MCP — by design. Its authors now recommend it over SWE-agent for everything.

Research harness · SWE-bench team (Princeton/Stanford)
Read second — what "more" looks like

Prime Agent

Persistent IPython REPL, recursive subagents that stay addressable after they finish, continual refinement of prompts and skills, an Agents View for inspecting sessions. Standardizes execution, recovery, verification and resource accounting while leaving strategy to the model.

Research harness · MIT · 30% → 95.5% on ARC-AGI-3
If you would rather assemble than write

Pi SDK — pi-ai, pi-agent-core

TypeScript packages behind the Pi harness: unified LLM API (15+ providers), agent loop, tools and state, usable on their own. Explicitly positioned for building your own harness from real parts.

Harness SDK · MIT · 16.7M npm/mo (pi-ai)
If you are shipping a product agent

Claude Agent SDK · OpenAI Agents SDK · Deep Agents · eve

Claude Agent SDK gives you Claude Code's loop and tools in-process (Claude only; 45.9M npm/mo). OpenAI's SDK is MIT with a hosted Agents API in US-only public beta. Deep Agents is the opinionated LangGraph-based library (subagents, filesystem backends, memory, skills, MCP). eve defines agents as conventional folders (Apache-2.0).

Harness SDK category · 6 of the 51 tools
To watch the frontier move

Exo · fx · Omnigent

Exo (Rust, MIT) is a harness that reads and edits its own code with an append-only event log as the safety record — and stopped early enough to be the cheapest per task. fx (Vercel Labs, Zig, ~7.8 MiB) is a tiny embeddable harness. Omnigent (Apache-2.0, alpha) composes and controls across harnesses.

07

Traps the papers already paid for

Trap 01
Stop hand-writing ReAct scaffolding. Models interleave thought and action natively now, so an explicit "Thought:/Action:" template is a harness imposing a shape the model already has.
Trap 02
Keep history linear. When the trajectory is the message list, debugging and fine-tuning both become trivial and you can diff exactly what the model saw.
Trap 03
Never let the model assert success. The completion signal must return as an observation from real execution, not as text the model produced.
Trap 04
One action per step, isolated process per action. A persistent shell session buys convenience and costs you sandboxing, reproducibility and parallel scale-up.
Trap 05
Unbounded tools are not the goal. Once the action is code, the tool list is already infinite — a persistent REPL generalizes better than twenty hand-written tools.
Trap 06
Budget tokens, not calls, and log the cost per task. The cheapest harness in the collection is cheapest partly because it stops early — early stopping is a harness feature.
Trap 07
Don't confuse a harness failure with a model failure. Sandboxing, recovery and resource accounting are your job; strategy is the model's.
Trap 08
Don't optimize prompts in the dark. There is no gradient through a prompt, so DSPy searched over them and GEPA read its own failed traces — both need the traces you should already be logging.
